# arfix

**بيصلح ظهور النص العربي المكسور في التيرمنال — مبني خصيصًا لـ Termux وأي توزيعة لينكس مبنية على Debian.**

## المشكلة

Termux والكتير من بيئات التيرمنال البسيطة في لينكس مش بتنفّذ حاجتين ضروريتين عشان العربي (وأي لغة RTL تانية) تظهر صح:

1. **Contextual shaping (تشكيل الحروف حسب السياق)** — الحرف العربي بيغيّر شكله حسب مكانه في الكلمة (منفصل، أول الكلمة، وسط الكلمة، آخرها). التيرمنال اللي مش بيعمل shaping بيطبع كل حرف بشكله المنفصل، مقطوع عن جيرانه.
2. **Bidirectional (BiDi) reordering (ترتيب اتجاه الكتابة)** — العربي بيتقرا من اليمين للشمال، لكن النص نفسه متخزن في الذاكرة من الشمال لليمين (الترتيب المنطقي). التيرمنال اللي مش بيطبّق خوارزمية Unicode BiDi بيطبع الحروف بترتيب بصري غلط.

النتيجة: نص المفروض يتقرا ككلمة متصلة بيطلع حروف مقطوعة ومعكوسة — مش مفهوم وشكله مكسور بصريًا.

المشكلة دي مش في الخط، وتركيب خط "أحسن" مش هيحلها. التيرمنال نفسه محتاج دعم shaping/BiDi ومش موجود عنده أصلاً. Termux تحديدًا شغال على Bionic libc بتاعة أندرويد مش glibc، وناقصها بنية الـ locale ومسار الـ rendering اللي تيرمنالات لينكس العادية بتعتمد عليه في الموضوع ده.

## الحل

`arfix` بيعمل الـ shaping والـ BiDi reordering **في السوفتوير، قبل ما يطبع**، فالتيرمنال مش محتاج يعملهم خالص. لما النص يوصل للتيرمنال، يكون بالفعل بالشكل الصح، متصل، ومرتب بصريًا — والتيرمنال بس بيطبعه زي أي نص عادي.

ده بيشتغل مع **أي خط عادي** فيه رموز يونيكود عربي. مش محتاج خط خاص، ولا إعدادات locale في النظام، ولا تغيير الـ terminal emulator.

### ليه بيتركب نضيف على Termux تحديدًا

النسخ الأقدم من الأداة دي كانت معتمدة على مكتبة `python-bidi` عشان الـ BiDi reordering. النسخ الحديثة من `python-bidi` محتاجة تجميع (compile) امتداد Rust عن طريق `maturin`، و`rustup` مش بيدعم الـ target بتاع أندرويد (`aarch64-unknown-linux-android`) — فالتركيب بيفشل تمامًا على Termux.

`arfix` بيتجنب المشكلة دي خالص. معتمد بس على مكتبة [`arabic-reshaper`](https://pypi.org/project/arabic-reshaper/) (بايثون خالص، من غير أي امتدادات مجمّعة) للـ shaping، وعامل بنفسه منطق BiDi بسيط وبايثون خالص للحالة الشائعة في output التيرمنال (سطر عربي، ممكن يكون فيه لاتيني أو أرقام مخلوطة معاه). من غير Rust، من غير أي خطوة build أصلية، من غير أي compiler — التركيب فوري على Termux، وعلى أي توزيعة مبنية على Debian، من غير أي مشاكل.

## المميزات

- **`arfix`** — يصلح النص العربي مباشرة، من argument، أو pipe، أو ملف
- **`smartcat`** — يشغّل أي أمر ويصلح الـ output بتاعه لحظيًا، سطر بسطر، أول ما يطلع
- **Auto-wrap shell hook** — اختياريًا بيخلي `cat`، `echo`، `grep`، `head`، و`tail` تصلح العربي تلقائيًا، من غير ما تكتب حاجة زيادة
- **النص غير العربي مش بيتلمس خالص** — السطور اللي مفيهاش حروف عربي بتعدي من غير أي تغيير، فمفيش حاجة تانية في شغلك هتتبوظ
- **من غير أي اعتماديات (dependencies) أصلية** — بايثون خالص، بيتركب فورًا على Termux وأي توزيعة مبنية على Debian
- **حزم `.deb` مخصصة** لـ Termux وأنظمة Debian-based، متبنية من نفس السورس
- **إزالة كاملة وأوتوماتيكية بالكامل** — أمر واحد بيمسح كل حاجة اتركبت

## المنصات المدعومة

`arfix` متبني ومتعبأ (packaged) خصيصًا لـ:

- **Termux** (أندرويد) — الهدف الأساسي اللي المشروع اتعمل عشانه
- **أي توزيعة لينكس مبنية على Debian** — Debian، Ubuntu، Linux Mint، Kali Linux، Pop!_OS، Raspberry Pi OS، MX Linux، elementary OS، Zorin OS، وأي توزيعة تانية مبنية على نظام حزم `dpkg`/`apt`

الاتنين بياخدوا حزم `.deb` مخصصة ومتكاملة (شوف [التثبيت](#التثبيت)). الأداة الأساسية كمان مجرد بايثون خالص باعتمادية بايثون واحدة بس، فبتتركب عن طريق `pip` على أي نظام شغال بايثون 3.7+ — بما فيها التوزيعات اللي مش مبنية على Debian — رغم إن دي مش الهدف الأساسي للتعبئة (packaging).

## التثبيت

### الطريقة 1 — حزمة `.deb` (الأفضل لـ Termux والتوزيعات المبنية على Debian)

ابني الحزم من السورس:

```bash
git clone https://github.com/MRX7014/arfix.git
cd arfix
bash packaging/build-deb.sh
```

ده بيطلعلك حزمتين منفصلتين، لأن Termux وأنظمة Debian العادية بيستخدموا هيكل نظام ملفات مختلف:

```bash
dpkg -i arfix-termux.deb    # Termux (أندرويد)
dpkg -i arfix-debian.deb    # Debian، Ubuntu، Mint، Kali، Pop!_OS، Raspberry Pi OS، وأي توزيعة تانية مبنية على Debian
```

كل حزمة بتركب حزمة البايثون، وتظبط أوامر `arfix` و`smartcat`، وتفعّل الـ shell auto-wrap hook — من غير أي أسئلة، من غير أي خطوات إضافية.

### الطريقة 2 — سكربت تركيب بأمر واحد

بيشتغل بنفس الطريقة على Termux أو أي توزيعة مبنية على Debian، من غير ما تحتاج `dpkg`:

```bash
git clone https://github.com/MRX7014/arfix.git
cd arfix
bash scripts/install.sh
```

### الطريقة 3 — pip (أي نظام شغال بايثون)

```bash
git clone https://github.com/MRX7014/arfix.git
cd arfix
pip install --break-system-packages .
```

مفيدة لو انت على نظام مش مبني على Debian (زي Arch أو Fedora) وعايز بس أوامر `arfix`/`smartcat` من غير تعبئة `.deb` أو إعداد الـ shell auto-wrap.

## الاستخدام

### سطر الأوامر

```bash
arfix "some arabic text here"          # يصلح ويطبع النص مباشرة
echo "some arabic text here" | arfix   # يصلح نص جاي من أمر تاني عن طريق pipe
cat notes.txt | arfix                  # يصلح نص جاي من ملف
arfix -f notes.txt                     # يصلح ويطبع محتوى ملف مباشرة
arfix -h                               # يعرض شرح كامل للاستخدام
arfix -u                               # يشيل arfix بالكامل وأوتوماتيكي
```

### `smartcat` — تشغيل تلقائي لأي أمر

بيشغل أمر ويصلح العربي في الـ output بتاعه لحظيًا، سطر بسطر أول ما يطلع:

```bash
smartcat cat notes.txt
smartcat ./my_script.sh
smartcat ping example.com
```

### Auto-wrap (من غير أي أمر خالص)

لو الـ shell hook كان مفعّل وقت التركيب (وده الافتراضي مع `install.sh` والحزمتين `.deb`)، الأوامر الشائعة بتتلف تلقائيًا لباقي جلسة التيرمنال:

```bash
cat notes.txt      # العربي في الـ output بيتصلح تلقائيًا
echo "..."         # نفس الحاجة
grep "..." file    # نفس الحاجة
head file.txt      # نفس الحاجة
tail file.txt      # نفس الحاجة
```

مش هتحتاج تكتب `arfix` أو `smartcat` خالص للحالات دي — وأي برنامج تفاعلي بيرسم الشاشة بالكامل (زي `vim`، `nano`، `htop`) مش بيتأثر، لأن دول بيرسموا على الشاشة مباشرة مش بيطبعوا سطور.

### كمكتبة بايثون

```python
from arfix import fix

print(fix("some arabic text here"))
```

`fix()` بتعالج النص سطر بسطر، ففواصل الأسطر الموجودة بتتحفظ والسطور اللي مفيهاش عربي بترجع زي ما هي من غير تغيير.

## الإزالة (Uninstalling)

```bash
arfix -u
```

ده أوتوماتيكي بالكامل ومحتاجش أي خطوة إضافية منك، سواء على Termux أو أي توزيعة مبنية على Debian:

1. بيشيل الـ auto-wrap block من `~/.bashrc`
2. بيشيل حزمة `arfix` بتاعة البايثون
3. بيشيل تسجيل حزمة `.deb`، لو arfix كان متركب بالطريقة دي

## هيكل المشروع

```
arfix/
├── arfix/
│   ├── __init__.py              # إعادة تصدير للـ public API (fix, main, إلخ)
│   ├── core.py                  # منطق اكتشاف العربي، الـ shaping، والـ BiDi
│   ├── cli.py                   # أوامر `arfix` / `smartcat` في سطر الأوامر
│   └── uninstall.py             # منطق الإزالة الكاملة والأوتوماتيكية لـ `arfix -u`
├── scripts/
│   ├── install.sh                # سكربت التركيب بأمر واحد
│   └── arfix-shell-hook.sh       # تعريفات دوال الشل لميزة الـ auto-wrap
├── packaging/
│   ├── build-deb.sh             # بيبني نسختي الـ .deb من السورس
│   ├── deb-termux/DEBIAN/       # control / postinst / prerm لنسخة Termux
│   └── deb-debian/DEBIAN/       # control / postinst / prerm لنسخة Debian-based
├── pyproject.toml               # بيانات الحزمة ونقاط الدخول
├── LICENSE
└── README.md
```

### تنظيم الكود

حزمة `arfix` مقسّمة حسب المسؤولية بدل ما تكون كلها في ملف واحد:

- **`core.py`** مالوش أي علاقة بالـ CLI أو التركيب — ده الجزء القابل لإعادة الاستخدام كمكتبة (`fix`, `fix_line`, `has_arabic`)، آمن تعمله import لوحده.
- **`cli.py`** مسؤول عن الـ argument parsing وأوامر `arfix`/`smartcat`، وبياخد من `core.py`.
- **`uninstall.py`** مسؤول عن تنظيف `.bashrc`، وحذف حزمة pip، ومنطق حذف الـ `.deb` بتاع `arfix -u`، منفصل عن الـ argument parsing.
- **`__init__.py`** بس بيعيد تصدير الـ public API، فـ `from arfix import fix` ونقاط الدخول في `pyproject.toml` (`arfix:main`, `arfix:run_wrapped`) فاضلة شغالة زي ما هي.

## طريقة عمل الأداة

1. **الاكتشاف (Detection)** — كل سطر بيتفحص عشان يلاقي حروف من نطاقات يونيكود العربي (العربي، الملحق العربي، العربي الموسّع-A، أشكال العرض العربية). السطور اللي مفيهاش حروف عربي بترجع زي ما هي.
2. **الـ Shaping** — للسطور اللي فيها عربي، `arabic_reshaper.reshape()` بيحوّل كل حرف لشكله الصح حسب السياق (منفصل، أول الكلمة، وسطها، أو آخرها) ويوصلهم ببعض.
3. **ترتيب الـ BiDi** — السطر بعد الـ shaping بيتقسم لأجزاء (runs) من نص عربي-أو-محايد مقابل نص لاتيني/أرقام/رموز. ترتيب الأجزاء بيتعكس عشان العرض البصري من اليمين لليسار، وترتيب الحروف جوه كل جزء عربي بيتعكس هو كمان (لأن الحروف بعد الـ shaping لسه متخزنة بالترتيب المنطقي/ترتيب الكتابة). ده بيغطي حالة الاستخدام الشائعة في output التيرمنال من غير ما يطبّق خوارزمية Unicode Bidirectional الكاملة.

## القيود

- بيغطي النص اللي بيتطبع سطر بسطر (`cat`، `echo`، output السكربتات، إلخ). مش بيصلح — ومينفعش يصلح — البرامج التفاعلية اللي بترسم الشاشة بالكامل (`vim`، `nano`، `htop`) لأنها بترسم على الشاشة مباشرة مش بتطبع سطور.
- حزم `.deb` متبنية خصيصًا لـ Termux وأنظمة Debian-based (`dpkg`/`apt`). مش هتشتغل على Arch Linux (`pacman`)، أو Fedora/RHEL (`rpm`)، أو أي توزيعة تانية مش مبنية على Debian — استخدم طريقة `pip` بدل كده عليهم.
- تطبيق الـ BiDi بيغطي الحالة الشائعة (نص عربي، ممكن يكون فيه لاتيني أو أرقام مخلوطة معاه) مش خوارزمية Unicode Bidirectional الكاملة. ده بيغطي كل تقريبًا استخدامات التيرمنال الواقعية لكنه مش محرك BiDi عام لمستندات معقدة متعددة اللغات.
